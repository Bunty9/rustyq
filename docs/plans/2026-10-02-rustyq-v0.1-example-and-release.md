# rustyq v0.1.0 — Embedder API, Reference Example, Trusted-Publishing Release

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make rustyq usable as a library in someone else's project, prove it with a complete end-to-end example application, and ship v0.1.0 to crates.io, PyPI and GHCR through a tag-triggered workflow that uses trusted publishing (OIDC) instead of long-lived tokens.

**Architecture:** `rustyq-core` becomes the embedding surface (migrations, transactional `enqueue`, typed payloads, permanent errors, status lookup); the server and clients are rewired on top of it. `examples/order-pipeline` is a workspace member that embeds rustyq the way an application would (own API + own worker binary + own business tables) and ships a `demo.sh` that asserts every feature end to end, run in CI. A `release.yml` workflow builds wheels/sdist/crates/image on `v*` tags and publishes behind GitHub environments that require the maintainer's approval.

**Tech Stack:** Rust 2021, tokio, axum 0.8, sqlx 0.8 (Postgres, runtime queries), PyO3 0.29 + maturin (abi3), GitHub Actions (`PyO3/maturin-action`, `pypa/gh-action-pypi-publish`, `rust-lang/crates-io-auth-action`, `docker/build-push-action`).

**Spec:** this document (design decisions below are the spec; the user request was: working end-to-end example as a strong reference for adopters, new release, trusted publishing setup, LinkedIn + dev.to posts kept locally in `./scratchpad/`).

## Global Constraints

- Commits authored by `Bunty9 <Bunty9@users.noreply.github.com>`; no AI attribution anywhere (commits, PRs, release notes, changelog).
- Library crates (`rustyq-core`, `rustyq-server`, `rustyq-client`) must not use `sqlx::query!`/`query_as!` macros: a downstream crate with `DATABASE_URL` set at compile time would make our macros connect to *their* database (verified in `sqlx-macros-core-0.8.6/src/query/mod.rs`: live mode whenever `DATABASE_URL` is set and `SQLX_OFFLINE` is not `true`). Use `sqlx::query`/`query_as::<_, T>` with `FromRow`. `sqlx::migrate!` is fine.
- Migrations live in `crates/core/migrations/` (must be inside the crate to be packaged); migrations stay append-only.
- Crates published: `rustyq-core`, `rustyq-server`, `rustyq-worker`, `rustyq-client` (the name `rustyq` on crates.io belongs to an unrelated 2016 crate). PyPI: `rustyq` (free). Container: `ghcr.io/bunty9/rustyq`.
- Version 0.1.0 everywhere (Cargo workspace, PyPI via `dynamic = ["version"]`).
- Tests: `SQLX_OFFLINE` no longer needed; `cargo test --workspace -- --test-threads=1` against `TEST_DATABASE_URL`.

## Review Focus

1. Downstream app with its own `DATABASE_URL` and its own sqlx migrations sharing `_sqlx_migrations` → `rustyq_core::migrate` must not fail on the app's versions (ignore-missing) and must document "use timestamp versions".
2. `enqueue` inside a caller's transaction that is rolled back → no job row and no worker wake-up (NOTIFY is transactional).
3. Handler returns `permanent(..)` wrapped in `.context(..)` → still goes straight to `dead`, attempts = 1.
4. Malformed payload (`payload_as` fails) in the example → job dead with readable `last_error`, worker keeps running.
5. Re-running the release workflow after a partial publish (some crates already on crates.io) → skips published versions instead of failing.

pub struct NewJob { pub queue: String, pub kind: String, pub payload: serde_json::Value,
                    pub priority: i16, pub delay: std::time::Duration, pub max_attempts: i32 }
impl NewJob {
    pub fn new(queue: impl Into<String>, kind: impl Into<String>, payload: serde_json::Value) -> Self; // priority 0, delay 0, max_attempts 5
    pub fn priority(self, p: i16) -> Self; pub fn delay(self, d: Duration) -> Self; pub fn max_attempts(self, n: i32) -> Self;
}
pub async fn enqueue<'e, E: sqlx::PgExecutor<'e>>(executor: E, job: &NewJob) -> sqlx::Result<Uuid>; // INSERT + pg_notify, one statement
impl Job { pub fn payload_as<T: serde::de::DeserializeOwned>(&self) -> Result<T, serde_json::Error>; }

                       pub run_at: DateTime<Utc>, pub locked_by: Option<String>, pub last_error: Option<String> }
pub async fn job_status<'e, E: sqlx::PgExecutor<'e>>(executor: E, id: Uuid) -> sqlx::Result<Option<JobStatus>>;
// rustyq_client
#[derive(Debug, Clone, Default)] pub struct EnqueueOptions { pub priority: i16, pub delay_secs: i64, pub max_attempts: Option<i32> }
pub async fn enqueue_with(&self, queue, kind, payload, opts: EnqueueOptions) -> Result<Uuid, Error>;
pub async fn status(&self, id: Uuid) -> Result<Option<JobStatus>, Error>;   // client-side JobStatus mirror
// HTTP: POST /jobs accepts optional "max_attempts" (1..=1000, default 5)
